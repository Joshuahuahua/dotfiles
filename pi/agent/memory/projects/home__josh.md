## Project memory
- Laptop Bluetooth issue RESOLVED (clean workaround, not root-cause fix): ASUS Vivobook K6602ZC (Linux Mint 22.1 Cinnamon, Ubuntu noble base), MediaTek MT7922 combo Wi-Fi/BT card (btusb/btmtk). Kernel 6.8.0-139-generic had a confirmed Bluetooth regression: NULL pointer dereference during btmtk firmware setup (btmtk_setup_firmware_79xx -> btmtk_usb_hci_wmt_sync -> usb_autopm_get_interface -> __pm_runtime_resume), hci0 never finished init. 6.8.0-138-generic confirmed working (adapter initializes cleanly, real BD address, headphones reconnect fine). Tracked upstream: Launchpad bug #2166561 ("6.8.0-139: btmtk NULL deref kills MT7922 Bluetooth and hangs resume") plus duplicates #2166487/#2166497/#2166509/#2166544/#2166569/#2166577 — all status "New" as of 2026-09-07, no fix yet. Note: Update Manager's other kernel series (6.11, 6.14, 6.17) are 'end of life' (no security updates) so were not used as alternatives; 7.0 is supported but untried since 138 already works.
  - First tried pinning GRUB_DEFAULT to a specific 6.8.0-138-generic advanced-options menu entry ID + `sudo update-grub` — this did NOT reliably take effect (system booted 139 again on next reboot despite grub.cfg showing the correct default; root cause not fully diagnosed, possibly recordfail/hidden-timeout interaction).
  - FINAL FIX: booted 6.8.0-138-generic manually via GRUB menu (hold Shift/Esc at boot to reveal the hidden menu), then used Linux Mint's Update Manager GUI (View > Linux Kernels) to fully uninstall linux-image-6.8.0-139-generic (+ modules/modules-extra). Confirmed via `dpkg -l | grep linux-image` and `/boot/vmlinuz-*` that 139 is gone and 138 is now the newest installed kernel. Also reset `/etc/default/grub` GRUB_DEFAULT back to `0` (removed the now-unneeded custom override) + `sudo update-grub`, since with 139 gone GRUB naturally boots the newest remaining kernel (138) with no fragile default-ID matching required. System is now in a clean, simple state.
  - Todo #7 tracks checking for an eventual upstream fix (via `apt list --upgradable | grep linux-image` for a kernel newer than 139, and Launchpad bug 2166561 status) — once fixed and installed via Update Manager, no GRUB changes needed at all; the new kernel just becomes default naturally. _(saved 2026-09-07)_
